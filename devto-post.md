# How I Built 28 Open Source Projects in One Week

*A practical guide to building a GitHub presence that actually matters*

---

## The Problem

Most GitHub profiles are boring. A few half-finished projects, maybe a fork or two, and nothing that shows real engineering ability.

I wanted to build something different — a collection of genuinely useful tools and resources that people would actually star and use.

## The Strategy

I focused on three things:

1. **Solve real problems** — Every project addresses a specific pain point developers face daily
2. **Make it immediately useful** — Copy-paste a rule file, run one command, get instant value
3. **Write like a human** — No AI-generated fluff, just practical advice from real experience

## What I Built

### The Core Tools

**vibe-check** — A CLI that scores how AI-friendly your project is:
```bash
npx vibe-check
# Score: 83/100 | Grade: A
```

**commit-ai** — AI writes your commit messages from staged changes:
```bash
npx commit-ai
# feat(auth): add OAuth2 login flow
```

### The Knowledge Base

**awesome-ai-rules** — 20 production-ready rules for AI coding assistants. Copy-paste a rule file and your AI instantly writes better code.

**awesome-mcp-servers** — 9 verified MCP servers for Cursor, Claude Code, and Kimi Code.

**awesome-interview-skills** — 14 skills covering algorithms, system design, behavioral questions, and salary negotiation.

### The Learning Resources

**build-your-own-x-cn** — 10 hands-on tutorials for building technologies from scratch (Chinese version of the famous build-your-own-x).

**system-design-interview** — Complete system design interview prep with ASCII diagrams and capacity estimation.

**ai-agent-architectures** — 7 AI agent patterns with production code examples.

## Key Lessons

### 1. Consistency Beats Perfection

Every project follows the same structure:
- Bilingual README (English + Chinese)
- MIT License
- Contributing guide
- Security policy
- GitHub Actions CI

This makes each project look professional and trustworthy.

### 2. Solve the "Last Mile" Problem

Don't just list tools — show exactly how to use them. Every skill file includes:
- When to use it
- Step-by-step workflow
- Copy-paste templates
- Common mistakes to avoid

### 3. Cross-Link Everything

Each project references the others, creating a network effect. Someone who finds one project discovers all 28.

## The Results

- 28 public repositories
- 200+ content files
- All projects have bilingual documentation
- All projects have proper CI/CD setup

# 我如何在一周内构建了 28 个开源项目

*一个关于如何建立真正有价值的 GitHub 影响力的实用指南*

---

## 问题

大多数 GitHub 主页都很无聊。几个半成品项目，可能还有一些 fork，没有什么能展示真正的工程能力。

我想做点不一样的东西——一套真正有用的工具和资源，人们会真的 star 和使用。

## 策略

我专注于三件事：

1. **解决真实问题** — 每个项目都解决开发者每天面临的具体痛点
2. **立即可用** — 复制粘贴一个规则文件，运行一条命令，立刻获得价值
3. **像人一样写作** — 没有 AI 生成的废话，只有来自真实经验的实用建议

## 我构建了什么

### 核心工具

**vibe-check** — 检查项目 AI 友好度的 CLI 工具
**commit-ai** — AI 根据暂存的更改生成 commit message

### 知识库

**awesome-ai-rules** — 20 个生产级 AI 编程规则
**awesome-mcp-servers** — 9 个验证过的 MCP 服务器
**awesome-interview-skills** — 14 个面试准备技能

### 学习资源

**build-your-own-x-cn** — 10 个动手教程（从零构建技术）
**system-design-interview** — 系统设计面试准备
**ai-agent-architectures** — 7 种 AI Agent 架构模式

## 关键经验

### 1. 一致性胜过完美

每个项目都遵循相同的结构：双语 README、MIT 许可证、贡献指南、安全策略、GitHub Actions CI。

### 2. 解决"最后一公里"问题

不要只列工具——要展示如何使用它们。

### 3. 交叉链接

每个项目都引用其他项目，形成网络效应。
